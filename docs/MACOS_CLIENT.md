# macOS Client (Apple Silicon)

The current-main client supports Apple Silicon Macs on macOS 11 or newer. It
uses the same enrollment API and FRP 0.70.1 pin as the Linux client. Intel Macs
are not supported.

## Requirements

- Apple Silicon (`arm64`)
- macOS 11 Big Sur or newer
- `sudo`, launchd, `curl`, `openssl`, `python3`, `tar`, and `shasum`

The installer does not enable Remote Login, change the firewall, create users,
or install Homebrew packages. Install missing Command Line Tools with
`xcode-select --install`.

## Layout

Runtime state, configuration, identity, libraries, and the pinned `frpc`
binary live below `/Library/Application Support/frp-auto-deploy`. The
LaunchDaemon is
`/Library/LaunchDaemons/com.datarelay.frp-auto-deploy.frpc.plist`.

User-facing `frpctl` and `frp-client` commands are installed below the prefix
reported by `brew --prefix`, with `/usr/local` as the fallback. The root
LaunchDaemon never executes a Homebrew-prefix binary.

## Install and enrollment

Use the existing client enrollment command generated by the 2.1.3 server:

```bash
curl -fsSL <bootstrap-client-url> | sudo env \
  FRP_ALLOCATOR_URL=... FRP_ALLOCATOR_CA_SHA256=... \
  FRP_BOOTSTRAP_TICKET=... FRP_ZERO_TOUCH=1 bash
```

The shared bootstrap detects Darwin independently, rejects Intel/Rosetta
shells, downloads `frp_0.70.1_darwin_arm64.tar.gz`, and verifies SHA-256
`cfa733b5a261c1647edee3c1fc4133d2542989b28f5602e81d47fc821d25c55f`.

## Service control

Normal client commands remain `sudo frpctl` and `sudo frp-client`. Direct
launchd inspection is:

```bash
sudo launchctl print system/com.datarelay.frp-auto-deploy.frpc
```

Daemon output is written to `logs/frpc.out.log` and `logs/frpc.err.log` under
the state root.

## Uninstall

Run `sudo frpctl uninstall` or the client uninstaller. Local files and the
LaunchDaemon are removed. Server-side enrollment records and port reservations
are intentionally retained and must be released explicitly on the server.
